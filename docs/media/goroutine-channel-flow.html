Beginner Guide: Goroutines and Channels in Your Program

This page is designed for learning. The diagram scales to screen width, and the steps below explain exactly what happens in runtime using the same 6 numbered steps as the image.

Step-by-Step Flow

  1. Step 1 (blue) - start receiveOrders goroutine: main launches receiveOrders. No wait yet in main; receiveOrders later blocks when sending on receivedOrdersCh until a receiver is ready.
  2. Step 2 (blue) - start validateOrders goroutine: main launches validateOrders. validateOrders immediately blocks on order := <-in until receiveOrders sends.
  3. Step 3 (blue) - send to receivedOrdersCh: receiveOrders unmarshals first JSON and attempts out <- newOrder. This send blocks until validateOrders is waiting on the matching receive.
  4. Step 4 (blue) - validateOrders receives: the blocked receive in validateOrders is satisfied by step 3. After receive succeeds, validateOrders continues with the quantity check.
  5. Step 5 (green) OR Step 6 (pink) - route to output channel: validateOrders sends to validOrderCh (green) or invalidOrderCh (pink). That send blocks until the corresponding printer goroutine is waiting to receive.
  6. Final wake-up pattern: the matching printer goroutine receives, prints, then calls wg.Done(). main is blocked on wg.Wait() and resumes only after that done signal.

Tiny Blocking Timeline

T1-T2: validateOrders waits on <-in.

T3-T4: receiveOrders send and validateOrders receive synchronize; both continue.

T5-T6: main waits on wg.Wait() until the chosen printer goroutine receives, prints, and calls wg.Done().

Path Outcomes

Current input (first quantity = 5)

Branch taken: green (valid). The valid printer receives from validOrderCh, prints, and unblocks main via wg.Done(). The invalid printer remains blocked waiting on invalidOrderCh.

If first quantity is changed to -5

Branch taken: pink (invalid). The invalid printer receives invalidOrder and prints the error. The valid printer remains blocked waiting on validOrderCh.

Why only one order is routed

validateOrders performs one receive and does not loop. So only the first parsed order is validated and routed in this version.

Learning tip: think of a channel as a handoff point where one goroutine sends and another receives.
